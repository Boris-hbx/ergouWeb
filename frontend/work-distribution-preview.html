设计要点（PM 草稿）

1. 第 5 个视图叫「分布」（不叫"标签"）

  • 视图 seg：表格 / 看板 / 日历 / 人员 / 分布，5 视图
  • 取名"分布"是因为它本质是动态选维度看分布，不仅服务"标签"
  • 解决问题：哪个维度下哪个值任务多 / 谁有逾期 / 哪个值是空

2. 维度选择器（顶部）

  • 横排 seg：列出所有可分组的列 —— 所有 multi 列 + 所有 select / status 列
  • 列名后面带类型标签（multi / select / status）—— 帮助理解
  • 默认选第 1 个 multi 列（"标签"）
  • 新增 multi 列后该选择器自动出现新选项（"列由配置驱动"原则）

3. 气泡 + 卡片墙（复用人员视图形态）

  • 上半气泡：每个值一个气泡，大小=任务数（对数缩放 60-110px），颜色=逾期/P0/正常/灰
  • 下半卡片墙：每个值一张卡，列出该值下的任务（点 → 打开 T-100 抽屉）
  • 点气泡 → 滚到对应卡片 + 高亮

4. multi 字段的特殊处理

  • multi 一个任务可有多个标签 → 该任务在每个标签的卡片里都出现一次（合理的，否则任务"归属"会模糊）
  • 每个出现处右侧显示「+N 标签」灰色提示，表明这任务还有其它标签
  • 顶部"统计"行：共 N 任务 · 跨 M 个标签 · K 条未标记（即该 multi 字段为空的任务数）

5. 「未标记」永远是最后一个气泡 / 卡片

  • 灰底 + 虚线描边，区别于真实标签
  • 提醒用户"有些任务还没贴标签，要不要补"

6. 不做的事

  • ❌ 不做"拖动转移标签"：multi 字段一个任务多个标签，拖动语义模糊（是改还是加？）；改标签走 T-100 抽屉
  • ❌ 不做关系网络图（标签共现网络）：过度设计；除非未来有明确需求
  • ❌ 不做手机端（按 memory 规则）

7. 内置「标签」列（默认种入）

  • 在 work_columns 表的内置种子里加第 10 行：{name:'标签', type:'multi', options:[], builtin:true, position:10}
  • 每个 task 默认空，用户自由打标签；分布视图开箱即用
  • 需后端迁移：现有用户的 work_columns 表也要补上这行（IDEMPOTENT INSERT，只对没该行的用户加）

8. 实施成本

  • 1 个新文件 frontend/assets/js/work-distribution.js（复用 work-person 的 80% 代码）
  • work.css 加 ~30 行（维度选择器 + chip 样式）
  • 后端 1 行迁移加内置「标签」列种子；其它逻辑全前端
  • 预估 1 天

9. 时间 Tab 叠加

  • 遵循全局时间 Tab：今日 + 分布 = 只统计今日任务的标签分布
  • 切到分布视图时 Tab 保留（与其它视图行为一致）
