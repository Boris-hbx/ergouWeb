工具集 (tools.json 草案)

create_work_task
新建工作任务。assignee 留空 = 未指派。
title: string // 必填 assignee: string? // 纯文本 level: enum? // 院/所/组/个人 freq: enum? // 一次性/每周/每月/每季 status: enum? // todo|doing|blocked|done (默认 todo) priority: enum? // P0|mid|low (默认 mid) due_date: date? // YYYY-MM-DD desc: string? // 长文本简介
返回：{ id, title, ... }，含完整新建任务对象，用于 inline 展示任务卡。
update_work_task
部分更新。id 必填，其他字段传啥更新啥。
id: number // 必填 title?: string assignee?: string level?: enum freq?: enum status?: enum priority?: enum due_date?: date | null // null = 清空 progress?: number // 0-100 desc?: string
返回：{ id, ... }，更新后完整对象。
边界：status=done 时自动 progress=100；progress=100 时自动 status=done（与现有 work-board 拖拽逻辑一致）。
query_work_tasks
查询任务列表。所有筛选条件 AND；不传则返回最近 10 条。
q?: string // 标题/简介模糊搜 assignee?: string // 精确 level?: enum status?: enum // 单值 status_not?: enum // 排除该 status (常用: 排除 done) priority?: enum due_before?: date // 截止日 ≤ due_after?: date // 截止日 ≥ has_overdue?: boolean // = due_before(today) AND status≠done limit?: number // 默认 10, 最大 50
返回：{ count, tasks: [...], summary: { overdue, p0, by_status } }。
summary 让阿宝可以一句话概述："5 条未完成，1 条逾期，1 条 P0"。

设计要点（PM 草稿）

  • 3 个工具足够：CRUD 的 D（删除）由 update_work_task 改 status 或表格 UI 走，不开 LLM delete 口子，避免误删。
  • 不引入 batch_update：批量操作走「query → 逐条 update + 二次确认」，慢一点但安全（场景 5）。Phase 3 视使用频率再决定要不要 update_work_tasks。
  • 消歧策略（场景 2）：assignee 是文本字段，阿宝看历史 assignee 集合，找 fuzzy 匹配 >1 时弹候选；候选数据从 query_work_tasks 的隐式聚合得到。
  • 系统 prompt 要加：① 工作任务 vs 个人 todo 的区别（场景 6）；② 批量操作必须二次确认；③ 找不到任务时建议搜标题而不是猜编号（场景 7）。
  • UI 内嵌任务卡：阿宝消息里 inline 显示 task-card，点击 → 打开抽屉（复用 T-100）；列表 list-card 点击行 → 同样开抽屉。
  • 跨端一致：工具名 / 参数必须与 ergouPM 的 llm/tools.json 一致，Android / 鸿蒙后续接入用同一份；按 ADR-004 命名规范。
  • 实施分两步：① 后端 tool dispatch（Rust 端在 routes/chat.rs tool 循环里 match 新工具，3 个 handler 直接调 work_tasks/columns 现有 service）；② 前端聊天面板内嵌 task-card / list-card 渲染逻辑。后端独立可测，前端独立可测。
  • 同步要求：完工时 llm/tools.json 必须 update（铁律），不只是 Web 端 hardcode。
