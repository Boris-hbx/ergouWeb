设计要点（PM 草稿）

1. 进入方式

  • 工作 Hub 第 2 张卡 📊 周报，与「任务表」并列
  • 独立路由 /work/report，不嵌在表格视图里
  • 左侧栏可加二级入口"工作 › 周报"

2. AI 总结卡（顶部）

  • 阿宝调 query_work_tasks 自动算出周内数据，写 2-3 句话总结
  • 关键洞察：完成数 / 逾期红灯 / 下周排期提醒
  • 实施时调阿宝可串：服务端 SSE 流式生成 + 缓存（同周内重读不重新生成）

3. 4 个核心指标

  • 本周完成 · 本周新增 · 逾期未完成 · 完成率
  • 每项都带「与上周对比」delta（↑+3 / ↓-1 / 持平）
  • 逾期数用红色强调；完成率用百分数

4. Section 折叠卡（默认展开 / 折叠状态）

  • 人员产出榜：完成数横向 bar，最长者占满；右侧带 P0 / 逾期徽章——一眼看负载
  • 本周完成：列表前 5 条 + 「展开全部」
  • 下周到期前瞻：默认展开，PI 排周计划用
  • 逾期未完成：红色高亮，必须显眼
  • 本周新增：默认折叠（信息量低，需要时点开）

5. 时间窗口

  • 本周（默认）/ 上周 / 本月 / 自定义
  • 支持左右翻周（‹ ›）查历史报告
  • 本周日期范围：ISO 周一为周首

6. 导出能力

  • 复制 Markdown：序列化整个报告为 MD（标题 + 列表 + 表格），用 navigator.clipboard.writeText，可贴邮件 / Notion
  • 发邮件：mailto: 链接预填主题 + 内容
  • 导出 PDF：CSS print stylesheet + window.print()；浏览器原生 PDF 保存
  • 让阿宝润色：上下文塞给阿宝让他写正式版（带敬语、避开内部代号）—— 这是 PI 的痒点：原报告太干，要给所里看需要润色

7. 数据来源

  • 100% 复用 work_tasks 表，无需新表
  • 完成时间：MVP 用 updated_at AND status === 'done' 近似（不够准但能用）；准确版需 completed_at 字段或 work_task_events 事件溯源——见 Phase 2.5
  • 聚合逻辑：48 条任务级别，纯前端 filter 完全 OK；Phase 2 后端可加 GET /api/work/report?period=week&date=YYYY-MM-DD 优化

8. 实施成本

  • 1 个新文件 frontend/assets/js/work-report.js + 复用 work.css
  • HTML 段加在 work-view 容器里（路由切换显示）
  • 不动后端（MVP）；Phase 2 加 get_work_report LLM 工具让阿宝可聊天问"上周报告"
  • 预估 1 天 + AI 总结卡接入再 0.5 天

9. 不做 / 后续

  • ❌ 图表（饼图/柱图 chart.js）：本期用横向 bar + 数字够了，避免引入图表库
  • ❌ 多人对比图、燃尽图：科研 PI 用不上
  • ⏳ Phase 2.5：work_task_events 事件溯源 → 完整时间线 + 准确完成时间
  • ⏳ Phase 3：定时邮件订阅（每周日晚上自动发周报到邮箱）
