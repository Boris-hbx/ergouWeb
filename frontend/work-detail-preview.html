# 任务 责任人 层级 频率 状态 优先级 截止日 进度

设计说明（PM 草稿）

  • 形态：右侧滑入的 540px 抽屉（手机全屏），背景表格仍可见且可点切换，不是 modal。Linear/Asana/Notion 通用做法。
  • 关闭方式：✕ 按钮 / Esc / 点蒙层 / 切到其它视图（自动关）。
  • 上下任务导航：抽屉头部 ↑ ↓ 按钮（含计数 5/28），快捷键全局生效。让你能连续看任务而不用关→点→关→点。
  • 就地编辑：标题点一下变 input；元数据字段点一下高亮 + 弹出 select / picker（复用 T-095 抽出的 dialog 组件）；简介就是 textarea，失焦或 Cmd+Enter 保存。
  • 复用 dialog：进度条点击 → openProgressDialog（T-095）；标题/数字 → openTextInputDialog；日期 → datepicker.js。不要新写组件。
  • 活动时间线：按事件溯源记录（progress变化、status变化、assignee变化、创建/编辑），来源 = events/ledger.jsonl 同等机制（任务级 ledger，建议新建 work_task_events 表 or 复用 audit log）；MVP 可先只显示「创建 / 编辑」两条。
  • 抽屉宽度：540px（桌面默认），可拖左边手柄调整（MVP 不做，Phase 2 加）。
  • 哪里能打开抽屉：① 表格行任意空白处单击 ② 看板卡片点击 ③ 日历项点击 ④ 人员卡片任务标题点击。不打断现有单元格内联编辑——点单元格里的药丸/进度条仍走原弹层逻辑。
  • 实施成本：1 个新文件 work-detail.js + work.css 加 ~150 行；复用 T-095 的 dialog；后端无变；活动时间线如果做要 1 张新表或扩展 events 系统（看后端排期）。
