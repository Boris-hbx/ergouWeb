### 用例：抵御通过 AI 工具调用的 SQL 注入攻击

**主要参与者：** 攻击者（通过构造 AI 对话）
**范围：** Next 后端 — tool_executor、admin 路由
**层级：** 用户目标

**干系人与利益：**
- 攻击者 — 利用 AI 工具调用窃取或破坏数据
- 系统所有者 — 保护数据库完整性和用户隐私
- 用户 — 自己的数据不能被其他用户访问

**前置条件：**
- 攻击者拥有有效会话（访客或注册用户）
- AI 聊天端点接受会查询数据库的工具调用

**成功保证（后置条件）：**
- 所有用户输入值均通过参数化绑定；没有原始字符串拼接进入 SQL
- 恶意输入返回正常错误或被忽略 — 无数据泄露

**触发条件：** 攻击者发送一条精心构造的聊天消息，操纵工具参数（如 period = `"1; DROP TABLE todos--"`）

**主成功场景：**
1. 攻击者发送聊天消息，触发 `tool_get_statistics`，传入构造的 `period` 值。
2. 系统收到工具调用，通过白名单将 `period` 映射为参数化 WHERE 子句。
3. 系统仅使用绑定参数执行查询。
4. 系统返回正常统计数据（或在 period 无法识别时返回错误）。
5. 注入的 SQL 未被执行。

**扩展：**
- 2a. period 值不在白名单中：系统默认为"全部时间"或返回错误，不使用原始值构建 SQL。
- 2b. 攻击者针对 `tool_query_todos` 注入字段名：系统仅允许硬编码列名出现在 WHERE 子句中，未知字段被拒绝。
- 2c. 攻击者针对 `admin.rs` 的 `query_ai_period`：`since` 参数使用参数化日期表达式，不使用字符串拼接。

### 用例：抵御数据库备份的路径穿越攻击

**主要参与者：** 攻击者（或配置错误的环境）
**范围：** Next 后端 — db.rs 备份功能
**层级：** 子功能

**干系人与利益：**
- 系统所有者 — 备份必须只写入指定目录
- 用户 — 数据不能被暴露到任意文件路径

**前置条件：**
- 备份功能已配置，定期备份任务在运行

**成功保证（后置条件）：**
- 备份文件仅写入指定的备份目录内
- 包含 `../` 或绝对路径覆盖的路径组件被拒绝

**触发条件：** 备份程序使用包含穿越序列的路径执行

**主成功场景：**
1. 备份程序从配置目录 + 时间戳文件名构建备份路径。
2. 系统规范化路径，验证其在允许的备份目录内。
3. 系统使用验证后的路径执行 `VACUUM INTO`。
4. 备份文件在正确位置创建。

**扩展：**
- 2a. 规范化路径逃出备份目录：系统记录警告并中止备份，不写入文件。

### 用例：数据库错误时不崩溃

**主要参与者：** 用户（任意已认证用户）
**范围：** Next 后端 — 所有路由处理器
**层级：** 用户目标

**干系人与利益：**
- 用户 — 收到清晰的错误信息，而非连接中断
- 系统所有者 — 服务器保持运行；错误被记录以便诊断
- 其他用户 — 一个用户的异常请求不会导致所有人的服务崩溃

**前置条件：**
- 用户已认证并发起正常 API 请求
- 发生临时性数据库错误（磁盘满、表锁定、行损坏）

**成功保证（后置条件）：**
- 服务器进程保持存活（不发生 panic）
- 用户收到 JSON 错误响应：`{"success": false, "error": "..."}`
- 错误被记录上下文（端点、user_id、错误详情）

**触发条件：** 用户发起的 API 请求遇到数据库错误

**主成功场景：**
1. 用户发送请求（如创建待办、查看账单）。
2. 路由处理器准备并执行数据库查询。
3. 数据库返回错误（如 SQLITE_BUSY）。
4. 处理器捕获错误，记录带上下文的日志。
5. 处理器返回 HTTP 500 及 `{"success": false, "error": "内部错误"}`。
6. 服务器继续正常处理其他请求。

**扩展：**
- 3a. 错误发生在只读查询：处理器返回 HTTP 500，无数据被修改。
- 3b. 错误发生在事务中（如多步写入）：处理器回滚事务后返回错误，不持久化部分数据。
- 3c. 错误发生在后台任务（session 清理）：任务记录错误并在下个周期重试，不影响主请求处理。

### 用例：抵御用户生成内容的 XSS 攻击

**主要参与者：** 攻击者（注册用户）
**范围：** Next 前端 — 任务渲染、AI 聊天展示
**层级：** 用户目标

**干系人与利益：**
- 攻击者 — 通过任务标题、备注或 AI 回复注入脚本
- 受害用户 — 安全地查看共享/协作内容
- 系统所有者 — 用户提供的内容不执行脚本

**前置条件：**
- 攻击者创建了包含 `<script>` 标签或事件处理器的内容
- 受害者查看该内容（通过协作、分享或同一账号）

**成功保证（后置条件）：**
- 所有用户提供的文本通过安全 DOM API 插入（textContent、createElement）
- 没有 innerHTML 接收未转义的用户内容
- 用户生成的数据不触发脚本执行

**触发条件：** 前端渲染包含攻击载荷的任务卡片、AI 回复或共享项

**主成功场景：**
1. 攻击者创建标题为 `<img src=x onerror=alert(1)>` 的待办。
2. 前端渲染任务列表。
3. 渲染过程对所有用户输入字段使用 `textContent` 或 `escapeHtml()`。
4. 浏览器显示原始文本 `<img src=x onerror=alert(1)>` — 无脚本执行。

**扩展：**
- 3a. AI 回复包含类 HTML 内容：聊天渲染器在插入 DOM 前转义所有 AI 输出。
- 3b. 来自其他用户的共享项包含攻击载荷：无论内容来源，同样的转义规则适用。
- 3c. innerHTML 用于结构性 HTML（图标、布局）：innerHTML 只接收硬编码的 HTML 常量；用户数据通过子元素的 textContent 插入。

### 用例：乐观更新失败时优雅恢复

**主要参与者：** 用户
**范围：** Next 前端 — 任务操作
**层级：** 用户目标

**干系人与利益：**
- 用户 — UI 准确反映服务端状态，操作不会静默消失
- 系统所有者 — 不因写入失败导致静默数据丢失

**前置条件：**
- 用户正在查看已加载的任务列表
- 网络不稳定或服务器负载较高

**成功保证（后置条件）：**
- API 调用成功时：UI 反映新状态
- API 调用失败时：UI 恢复到操作前状态 + 用户看到错误提示

**触发条件：** 用户执行任务操作（完成、取消完成、移动、删除）

**主成功场景：**
1. 用户勾选某个任务为已完成。
2. 前端保存更新前状态，立即在 UI 上反映变更（乐观更新）。
3. 前端将更新发送到 API。
4. API 返回成功。
5. 前端确认更新 — 乐观状态变为正式状态。

**扩展：**
- 3a. 网络错误或 API 返回失败：前端将任务恢复到更新前状态，显示 `showToast("操作失败，请重试", "error")`。
- 3b. 用户在第一个操作完成前执行另一个操作：每个操作维护独立的回滚快照，互不影响。

### 用例：防止快速交互产生重复请求

**主要参与者：** 用户
**范围：** Next 前端 — 数据加载与变更操作
**层级：** 子功能

**干系人与利益：**
- 用户 — 看到一致的数据，不出现闪烁或重复内容
- 系统所有者 — 减少不必要的服务器负载

**前置条件：**
- 用户在任务列表视图
- 上一次数据加载仍在进行中

**成功保证（后置条件）：**
- 同一操作类型同时只有一个请求在途
- 始终应用最终响应；中间响应被丢弃

**触发条件：** 用户在上一次加载未完成时再次触发刷新（如下拉刷新、切换标签页、快速导航）

**主成功场景：**
1. 用户进入任务列表，`loadItems()` 触发。
2. 加载中，用户切换标签页后返回 — `loadItems()` 再次触发。
3. 系统检测到加载请求正在进行中，跳过重复请求。
4. 第一个请求完成并渲染数据。

**扩展：**
- 3a. 第一个请求已过时（用户更换了筛选条件）：系统取消第一个请求（或忽略其响应），使用当前参数发起新请求。
- 3b. 加载进行中发起变更请求（创建/更新/删除）：变更正常执行；如果加载响应在变更之后到达则被丢弃。

**待定问题：**
- 使用 AbortController 取消过时请求，还是通过 generation counter 忽略其响应？

### 用例：Guest 用户尝试使用受限功能时获得清晰引导

**主要参与者：** Guest 用户（体验模式）
**范围：** Next 前端 — 差旅、记账、好友等模块
**层级：** 用户目标

**干系人与利益：**
- Guest 用户 — 快速了解产品能力，不在无效操作上浪费时间
- 产品 — 引导 guest 转化为注册用户，而非让其困惑离开

**前置条件：**
- 用户以 guest 身份进入应用
- 页面顶部显示体验模式横幅

**成功保证（后置条件）：**
- Guest 受限功能的按钮在视觉上与可用按钮有明确区分
- 点击受限按钮时，立即在前端提示"注册解锁"，不发起后端请求
- 可用功能正常使用，不因 guest 身份被误拦截

**触发条件：** Guest 用户点击差旅创建按钮（FAB +）、记账创建按钮、AI 分析按钮、或分享按钮

**主成功场景：**
1. Guest 用户进入"生活 > 差旅"页面。
2. 页面展示 seed 示例数据，创建按钮（FAB +）显示为禁用态（半透明 + 锁标识）。
3. 用户点击 FAB +。
4. 前端立即弹出提示："体验模式不支持创建差旅，注册账户解锁"，附带注册链接。
5. 不发起任何后端 API 请求。
6. 用户可以继续浏览示例数据。

**扩展：**
- 2a. 记账模块：同样的禁用态 + 前端拦截模式应用于记账 FAB 和 AI 拍照分析按钮。
- 2b. 好友模块：设置页的好友管理区域显示"注册后可用"说明文案，而非静默隐藏。
- 2c. 分享功能：分享按钮显示禁用态；点击提示注册。
- 4a. 用户点击注册链接：跳转到登录/注册页面，现有 guest 数据可在注册后保留。

### 用例：Guest 用户感知并管理 AI 使用额度

**主要参与者：** Guest 用户
**范围：** Next 前端 + 后端 — 所有 AI 功能入口
**层级：** 用户目标

**干系人与利益：**
- Guest 用户 — 知道自己有多少 AI 额度、还剩多少、用完后怎么办
- 产品 — AI 额度是核心转化钩子，需要清晰展示

**前置条件：**
- 用户以 guest 身份登录，初始 AI 额度为 21 次
- 至少一个 AI 功能可用（聊天、记账 AI 分析、差旅 AI 分析、英语场景生成）

**成功保证（后置条件）：**
- 所有 AI 功能入口均显示"剩余 N 次"
- 每次消耗后，所有入口的计数同步更新
- 额度耗尽时，AI 按钮变为禁用态 + 注册引导
- 后端所有 AI 端点均正确扣减并返回 `ai_remaining`

**触发条件：** Guest 用户打开任意包含 AI 功能的页面

**主成功场景：**
1. Guest 用户打开阿宝聊天面板。
2. 输入框附近显示"AI 剩余 21 次"。
3. 用户发送一条消息，AI 回复后计数更新为 20。
4. 用户切换到记账页面，点击 AI 分析按钮。
5. 按钮旁同样显示"剩余 20 次"。
6. AI 分析完成后，计数更新为 19，所有入口同步。

**扩展：**
- 3a. 用户在英语场景生成中使用 AI：后端返回 `ai_remaining`（当前缺失），前端同步更新。
- 3b. 用户在"此刻"（moment）中触发 AI：后端检查 guest 额度（当前缺失），正确扣减并返回剩余次数。
- 6a. 额度降至 3 次以下：显示醒目提示"AI 体验即将用完，注册解锁无限使用"。
- 6b. 额度耗尽（0 次）：所有 AI 按钮变为禁用态，显示"注册解锁"。输入框显示"AI 体验次数已用完"。

### 用例：Guest 模式下查看差旅详情获得一致的界面布局

**主要参与者：** Guest 用户
**范围：** Next 前端 — 差旅详情页
**层级：** 用户目标

**干系人与利益：**
- Guest 用户 — 浏览示例差旅时看到完整的产品形态，理解功能价值
- 产品 — 展示差旅模块的完整能力，激发注册意愿

**前置条件：**
- Guest 用户进入差旅列表，存在 seed 示例数据
- 用户点击某个示例差旅

**成功保证（后置条件）：**
- 差旅详情页布局与注册用户一致（相同的按钮位置、相同的信息区域）
- 受限按钮（编辑、分享、导出）显示禁用态而非隐藏
- 用户能理解"注册后可以做什么"

**触发条件：** Guest 用户点击差旅列表中的一个示例项

**主成功场景：**
1. 用户点击示例差旅"出差 - 上海"。
2. 详情页展示完整布局：顶部操作栏（分享 👥、编辑 ✏️、导出 ⬇️）、行程列表、费用明细。
3. 分享按钮和编辑按钮显示为禁用态（半透明）。
4. 用户点击禁用的编辑按钮，前端提示"注册解锁编辑功能"。
5. 导出按钮正常可用（允许 guest 导出示例数据体验功能）。
6. 行程列表中的 AI 分析按钮显示"剩余 N 次"。

**扩展：**
- 3a. 注册用户查看同一页面：所有按钮正常可用，无禁用态，无额度提示。
- 5a. 产品决策：如果导出也要限制 guest，则同样显示禁用态 + 注册提示。
