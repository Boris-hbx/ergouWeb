## Why

当前管理员功能藏在设置页底部的一个小面板里，只有纯只读统计和用户审批。随着系统功能增多（多 LLM 提供商、差旅协作、好友分享），需要一个**独立的、完备的管理员控制台**，让管理员能真正管理用户、配置系统、监控运行状态。

核心诉求：
- 管理员权限分级——不能随便给人用，但又要能委派部分管理能力
- 模型配置可视化——看清各模型 token 消耗和成本
- 系统健康可观测——不用 SSH 上服务器也能知道系统状态

## What Changes

### 独立管理员页面
- 从设置页的嵌入面板**升级为顶级独立视图**（电脑端左侧导航新增"管理"入口）
- 仅管理员角色可见，普通用户完全不显示该入口
- 响应式布局，电脑端优先（移动端可简化展示）

### 权限分级体系
- **BREAKING**: 扩展现有 `role` 字段，从 `admin/user` 二元改为三级：
  - `owner`：系统所有者（唯一），可授予/撤销 admin，可做一切操作
  - `admin`：管理员，可管理用户、查看监控、配置模型，**不可授予 admin 给他人**
  - `user`：普通用户，不可见管理界面
- Owner 可将用户提升为 admin 或降回 user
- Admin 可查看管理面板但不能变更权限

### 用户管理增强
- 用户列表：搜索、排序、筛选（按状态/角色/活跃度）
- 用户详情卡片：注册信息、最后活跃、功能使用量、AI 消耗量
- 操作：审批/拒绝、封禁/解封、角色变更（owner only）、强制下线
- 用户活跃度趋势图（DAU/WAU/MAU 折线）

### AI 对话监控
- 管理员可浏览所有用户的二狗对话记录（conversations + chat_messages）
- 按用户、按时间范围筛选
- 对话列表：标题、用户、消息数、token 消耗、创建时间
- 点击展开查看完整对话内容（用户消息 + AI 回复）
- 用途：质量监控、安全审查、问题排查、了解用户使用模式

### 模型配置与 AI 用量看板
- 各 LLM 提供商状态：Claude / Kimi / Doubao 的 API Key 配置状态（已配 / 未配 / 余额不足）
- Token 消耗总览：按提供商、按时间段（今日 / 7 天 / 30 天）汇总
- 分用户 AI 消耗排行：谁用了多少 token，哪个模型
- 模型选择策略配置：默认模型、fallback 顺序（只读展示当前配置，修改仍走环境变量——API Key 不入库，安全优先）
- 可选：每用户 token 限额设置

### 风险舆情监控
- **敏感内容检测**：利用二狗已有的安全巡逻机制（`report_security_event`），在管理面板集中展示
- **风险事件仪表盘**：按严重级别（low/medium/high）分类展示，高危事件置顶+红色醒目标记
- **风险事件详情**：关联到具体对话，一键跳转查看完整上下文（与对话监控联动）
- **风险用户画像**：标记多次触发安全事件的用户，显示事件频次和趋势
- **关键词/行为模式统计**：按 event_type 聚合（数据刺探、提示词攻击、伪造身份等）
- **通知机制**：高危事件实时推送给管理员（复用现有通知系统）

### 系统状态监控
- 服务器信息：版本号、启动时间、运行时长
- 数据库：文件大小、表行数、最后备份时间
- 存储：上传文件总大小、磁盘用量
- API 健康：最近错误率、平均响应时间（可选）

### 操作审计日志
- 记录管理员的所有操作（角色变更、封禁、配置修改等）
- 可查看、可筛选、不可删除

## Capabilities

### New Capabilities
- `admin-rbac`: 三级权限体系（owner/admin/user），权限授予与撤销，权限守卫
- `admin-user-mgmt`: 用户管理增强——列表搜索/排序/筛选、详情卡片、批量操作
- `admin-chat-monitor`: 二狗对话监控——浏览所有用户对话、按用户/时间筛选、查看完整对话内容
- `admin-ai-dashboard`: AI 模型配置面板 + token 消耗看板（按模型/用户/时段）
- `admin-risk-monitor`: 风险舆情监控——安全事件仪表盘、风险用户画像、事件-对话关联、高危通知
- `admin-system-monitor`: 系统状态监控——服务器、数据库、存储、健康检查
- `admin-audit-log`: 管理员操作审计日志——记录、查看、筛选

### Modified Capabilities
- `frontend-safety`: 前端路由守卫需适配三级权限，管理入口仅 owner/admin 可见
- `error-handling-hardening`: admin API 端点需统一错误处理与权限校验中间件

## Impact

- **后端**: `admin.rs` 大幅扩展，新增 8+ API 端点（含对话查询）；`auth.rs` 权限检查从二元改三级；`db.rs` 新增 `admin_audit_log` 表 + 用户表 role 值迁移
- **前端**: 新增 `admin-panel.js`（或重写 `admin.js`）+ `admin-panel.css`；`index.html` 新增管理视图容器
- **数据库**: `users.role` 值域扩展（`user` / `admin` / `owner`）；新增 `admin_audit_log` 表
- **兼容性**: 现有 `admin` 角色需迁移为 `owner`（首个管理员），**BREAKING** 但可通过 migration 自动处理
- **安全**: 所有新 API 必须严格校验权限层级，防止越权操作
